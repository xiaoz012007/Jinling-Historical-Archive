# EV-B-003-01 公式、约束与检验

令 `floor` 为向下取整，`ceil` 为向上取整。席位两次取整分别发生在装载和军民分配，避免小数人和“部分船只”。所有给定时长、比例、库存均为 I 参数。

| 构件 | 核心公式 |
|---|---|
| 可用列车服务 | `floor(每日槽位 × 天气窗口比例) × 陆路开放标志` |
| 每单位民用槽位 | `floor(floor(名义席位 × 装载实现率) × 平民席位比例)` |
| 可出勤汽车 | `floor(汽车池 × 油料机械可出勤比例)` |
| 汽车完整循环 | `floor(日工作分钟 × 天气窗口比例 / (去程 + 返程 + 装卸)) × 陆路开放标志` |
| 单程小船循环 | 窗口容纳去程与装卸则 1，否则 0；乘水路开放标志 |
| 开启回航的循环 | `floor(日工作分钟 × 天气窗口比例 / (去程 + 返程 + 装卸)) × 水路开放标志` |
| 可供小船航次 | `min(min(原点船初, 每日出勤上限) × 循环数, floor(码头总装载槽位 / 每船装载槽位))` |
| 小船民用能力 | `可供航次 × 每船民用槽位` |
| 步行集结能力 | `floor(floor(每日名义入口 × 天气窗口比例) × 编组实现率) × 陆路开放标志` |
| 单一路分配 | `min(本路线能力, 分配后尚余需求, 当日尚余共享入口)`，依次铁路、汽车、小船、步行 |
| 条件实际使用航次 | `ceil(小船分配人数 / 每船民用槽位)`，零分配/零槽位时为 0 |
| 出勤船只 | `ceil(使用航次 / 循环数)`，零循环为 0 |
| 船池结转 | `原点末 = 原点初 − 出勤船 + 返回船`；`返回船 = 出勤船 × 回航开关` |
| 北岸后续完成 | `min(floor(跨江人数 × 接运实现率), 每日接运上限)` |
| 步行完成 | `floor(步行出发 × 首段完成比例)` |
| 预设链条完成 | `铁路分配 + 汽车分配 + 北岸后续完成 + 步行完成` |

天气只折减一次：列车槽位、车辆/小船工作窗口、步行入口分别受约束，不在人数结果上再乘一遍。油料比例仅控制汽车出勤，不表示已掌握实际燃油吨数。码头槽位包含预留非平民部分；预留不是已发生的军运量。

人群恒等式每日成立：`初始需求 = 原点待出发 + 累计链条完成 + 步行待完成 + 北岸待转运`。所有已出发人群从原点需求扣除，即使尚未完成链条也不重新分配。默认等待者不跨日继续接运；这是保守的排队冻结简化，而不是历史停留结局。若要加入后续清队，必须增加按日待转库存的实际接运式并重新校验，不能把静态等待者直接加到完成数。

船池恒等式：`初始船池 = 原点船末 + 对岸船末`。实际用船不超过原点库存；开启闭合往返时当天使用的船全部返回。当前模型不表示在江中跨日未归、船只损失、临时调入或个体船速差异；这些未知限制通过不默认回航和共同风险截止来控制，并未伪造损失人数或船只。

名义首段槽位的计算不含天气、油料、装载、军民比例、码头、共享城门、需求上限折减。它为铁路名义槽位、汽车名义闭合循环席位、步行入口与小船名义航次席位之和。单程船池在全期只计一次；回航方案按闭合循环计。其单位是槽位，不能与历史人头或最终获救同义。

## 复算验证

Python 有 21 项通过测试：三案全部每日守恒，以及非法情景、缺项、负数、非整数资产、超界比例、零行程、非法回航值、空值、非有限数、超范围日期、零需求、低需求上限、共享入口、返航开关、零油料、零窗口、步行未完成库存、开始日期变更。

artifact-tool 工作簿分别切换三案，与 Python 每案 43 日 × 34 数值列逐格比较（共 4,386 格），并校验名义槽位。23 项单因素敏感性由同一活动计算区逐项修改后重算，与 Python 相同。6 项边界测试包括无需求、零窗口、空需求、负船池、非法情景，以及未选方案为空仍可计算/选中该空方案必须停止计算。最后恢复中案。

工作簿公式错误扫描为 0。全部 5 个表经渲染检查，逐日宽表分资源、分配、守恒三个窗口检查。导出后另检查 XML 公式错误和来源 ID。没有宣称经过 Microsoft Excel 桌面版实机计算；版本升级或公式修改应重新执行独立复算。

参数快照一致提示检查 25 个共同输入和 18 个组织情景输入，选择器变化不使比较快照过时。公式修改无法由这个提示检测，故必须同时保留模型版本和构建脚本；不要把“参数一致”解释为所有编辑都通过验证。

## 独立复核补充边界

model_data.json中的calendar_start、calendar_end和allocation_order是当前版本的说明元数据，不是可编辑驱动；可编辑计算输入限common_parameters与organization_parameters，情景由既定ID选择。改变日历基准或分配顺序属于改模型逻辑，必须同时修改代码与公式并重新验证。

F-003B-007的候选执行期为12月11–13日，与本模型默认11月27日–12月7日运输窗口不相交。boat_handling、handoff中的该关联只预留未来撤退阶段的机制接口，不表示F007造成了更早的运输改善。逐参数边界见FICTION_MODEL_LINK_SCOPE.csv；所有组织效果均是I测试输入。
