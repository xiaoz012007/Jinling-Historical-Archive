# 版权、许可与再利用政策

## 1. 仓库公开不等于全部内容可自由转载

本仓库可能包含第三方档案、网页、书籍、论文、照片、地图和司法材料。每一项内容必须单独判断权利状态。仓库根目录暂不设置覆盖全部第三方材料的统一许可证。

## 2. 内容类别

为每个文件或来源记录以下状态之一：

- public_domain：经核查属于公有领域；
- open_license：有明确开放许可，记录许可名称及链接；
- permission_granted：已取得可留档的授权；
- link_only：只提供合法来源链接和书目信息；
- citation_only：仅提供符合适用规则的必要引用及原创分析；
- rights_pending：授权状态待核；
- restricted：不得公开再分发。

## 3. 原创内容

项目成员自行撰写的研究说明、数据整理、原创注释和模型，应在文件中标明作者、日期和拟采用的许可。项目可在后续明确范围后，对原创文档考虑采用CC BY 4.0；对原创代码可考虑MIT或Apache-2.0。

在维护者明确批准前，不要将这些建议理解为已经生效的统一授权。

## 4. 第三方材料

- 不上传受版权保护的整本书、论文全文或未经许可的扫描件。
- 不上传版权状态不明的网页全文或照片原图。
- 不因资料可在线访问就推定允许重新发布。
- 对不能再分发的材料，提供准确书目信息、馆藏定位、官方链接、必要的原创摘要及引用定位。
- 公开档案也需检查具体发布条件、个人信息及使用限制。
- 引用应遵守适用法律和原始许可要求。

## 5. 网页快照

网页快照遵循WEB_SNAPSHOT_POLICY.md。内部保存快照与公开仓库发布快照必须分开判断。

## 6. 个人信息与敏感内容

不要公开私人联系方式、账户信息、非必要个人身份信息、登录凭据或与研究无关的个人数据。

## 7. 纠错与下架

若权利人提出有依据的版权或隐私问题，维护者应及时核查，并在核查期间限制相关文件的公开访问。删除或替换文件时记录原因；必要时检查Git历史中是否仍保留不应公开的内容，并按平台流程处理。

本文件是项目管理规范，不构成法律意见。存在疑问时，先不公开完整文件。
